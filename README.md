# ikora-lite

**軽さを最優先にした、7 バンドの Android イコライザ。**
音の処理は Android 内蔵のエフェクト（DynamicsProcessing）が audioserver の中で行い、
このアプリは設定画面と、エフェクトを付け外しするだけ。

- 対応: Android 9 (API 28) 〜 最新 (targetSdk 36 / Android 16)
- 出来上がり: `ikora-lite.apk` — **約 76 KB**
- 権限: **インストール時に自動で許可されるものが 4 つ**
  （`MODIFY_AUDIO_SETTINGS`、`FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_SPECIAL_USE`、`RECEIVE_BOOT_COMPLETED`）。
  通知の許可（`POST_NOTIFICATIONS`）は「常駐して待つ」か「全体モード」を ON にしたときだけ求める。
  確認ダイアログは一度も出ない。通知の権限も求めない。
  ほかに **DUMP** を宣言しているが、これはインストールでは許可されず、PC から
  `adb shell pm grant com.ikoralite android.permission.DUMP` を一度実行したときだけ有効になる。
  許可すると「今の音の流れ」が見える（下の「効いているものの表示」）。許可しなくても他は全部動く
- 依存ライブラリ: **無し**（AndroidX も Kotlin も使っていない）

## 使い方

1. インストールしたら**一度アプリを開く。** 開くまでは Android が「停止状態」として扱い、
   音楽アプリからの知らせが届かない。
2. 画面に案内が出ていたら（Android 12 以降）、ボタンからアプリ情報を開き、
   「アプリのバッテリー使用量」→「バックグラウンドでの使用を許可」→「制限なし」を選ぶ。
   機種によっては「バッテリー」→「制限なし」。この画面へ直接飛ぶには権限が
   もう一つ要るので、あえてアプリ情報までにしている。
3. あとは音楽アプリで再生を始めるだけ。設定を変えたいときにアプリを開く。

画面の中身:

- **ON / OFF**: OFF の間はフェーダーとプリセットが薄くなり、触れない
- **効いているか**: 「✓ ikora が効いています」か「✗ 効いていません（○○ が優先されています）」
- **今の音の流れ**: 下の「効いているものの表示」
- **プリセット**: フラット / 低音 / 高音 / 声。今の値を「＋ 保存」で名前を付けて保存でき、
  自分のプリセットは長押しで削除できる（同じ名前なら上書きを確認）。今の値と一致するプリセットには ✓ が付く
- **出力**: いまの設定がどの出力機器のものか。下の「出力機器ごとの設定」
- **BASS**（OFF・1〜5）: 低音を歪ませずに持ち上げる。下の「BASS の仕組み」
- **7 バンド**: 31, 88, 250, 700, 2k, 5.6k, 16k Hz。両端は 31 Hz と 16 kHz、その間を対数で等分し、
  真ん中が 700 Hz。±12 dB、0.5 dB 刻み。縦のフェーダーで、**列のどこを触っても掴める**。
  指を動かした分だけ動くので、触れただけでは値は変わらない
- **たたんである欄**（▸ で開く。開閉は覚えておく）: 動作の設定（全体モード・常駐して待つ）、使うイコライザ、
  詳しい状態（今の音の流れ・ほかの効果の調査）、診断。ほかの効果の調査は音の流れに一瞬触れるので、
  「詳しい状態」を開いたときと診断情報を送るときだけ行う
- **使うイコライザ**: 端末に入っているイコライザアプリの一覧。ikora 以外を選ぶと
  ikora を OFF にして、そのアプリの画面を開く。Android にはイコライザを一つに決める
  仕組みがなく、ほかのアプリを止めることもできないため

## 出力機器ごとの設定

同じカーブでも、本体スピーカーでは気にならない歪みが Bluetooth の WF-1000XM5 でだけ気になる、
ということがある（テスターの報告）。そこで 7 バンドと BASS を**出力機器ごとに覚え**、
出力が変わったらその機器で最後に使った設定に自動で切り替える。

- 分け方: 本体スピーカー / 有線イヤホン / USB（名前ごと）/ Bluetooth（**機器の名前ごと**）
- 今の出力は、Android 13 以降は音楽の実際の行き先（`getAudioDevicesForAttributes`）、
  それより前はつながっている機器の優先順（Bluetooth → USB → 有線 → スピーカー）で決める
- 切り替えは、機器の付け外しの知らせ（`AudioDeviceCallback`）と、そのあと 1 秒・3 秒後にも見直す
  （行き先が決まるまで少し遅れるため）。ほかに ikora のプロセス起動時と画面を開いたとき
- 初めての機器は、その時の設定を引き継いでから覚える
- フェーダー・プリセット・BASS を触ると、その時の出力の設定として保存する
- 画面の「出力: ○○ の設定」で、今どの機器の設定かが分かる。
  「動作の設定」の「出力機器ごとに設定を覚える」を OFF にすると、全機器で一つの設定に戻る

## BASS の仕組み

DynamicsProcessing に 2 帯域のコンプレッサー（MBC）とリミッターを足して作る。
Sony の Clear Bass と同じ考え方（歪ませずに低音を底上げ）で、同じ技術ではない。

- 150 Hz 以下の帯域を、段階ごとに +2 dB 持ち上げる（1: +2 … 5: +10 dB）
- その帯域が -12 dBFS を超えたら 4:1 で圧縮する。小さい低音はそのまま持ち上がり、
  大きい低音は膨らみすぎないので、上げても歪みにくい
- 最後に -1 dBFS のリミッターでクリップを防ぐ
- OFF のときは帯域を 1:1・0 dB にし、リミッターも止める。
  Xperia ではコンプレッサーの段を「無効」にしても処理エンジンが有効のままだったので
  （読み戻して確認）、段を止めるのではなく帯域そのものを素通しにしている
- 端末標準のイコライザで代用しているとき（全体モードで DynamicsProcessing を使えないとき）は、
  コンプレッサーが無いので単純な持ち上げ（60 Hz 以下で全量、150 Hz までで 0 へ）になる

## 効いているものの表示

DUMP を許可すると、audioserver が実際に処理している順に、効果と持ち主のアプリを出す。

```
YouTube Music  → Bluetooth
  ● ikora — DynamicsProcessing（EQ・音量など）
  ● システム — Music Volume Listener
  ↓ ほかのアプリの音と合流（全体）
  ○ オーディオ設定 — DAP（無効）
  ○ DseeService — DSEE（無効）
  ↓ Bluetooth
  （ヘッドホン本体のイコライザは、ここからは見えません）
```

● は有効、○ は無効。読むのは画面を開いている間だけ（2 秒ごと）。
ヘッドホン側のイコライザ（Sony Sound Connect など）はヘッドホンの中で処理されるので、
スマホからは見えない。

## 知らせを取りこぼす端末・知らせを出さない端末

- **常駐して待つ**: ikora を常に動かしておき、動的な受け口で知らせを受ける（Wavelet の通常モードと同じ形）。
  AQUOS R8 では、YT Music が鳴っているのに ikora に知らせが一度も届かなかった。受信テスト
  （ikora が前面にいるとき）は届き、同じ端末で Wavelet の通常モードは効いていた。
  **「常駐して待つ」を ON にしたら効いた**（v6、テスター確認）。YT Music は知らせを出していて、
  裏で止まっている ikora が知らせのために起こされていなかった。
- **全体モード**: 全体（セッション 0）に効果を付ける。知らせが要らない代わりに、端末の音すべてに効く。
  全体の DynamicsProcessing は他のアプリ（Xperia では volzz の音量調整）と 1 つのエンジンを共有し、
  後から付けた側が相手の設定を上書きしてしまう。そのため、すでにあれば触らず、
  端末標準のイコライザ（5 バンドで近似）を使う。ikora の DynamicsProcessing を手放すときは、
  先に全バンドを 0 dB に戻してから外す。
- どちらも ON にするときだけ通知の許可を求める（常駐の表示を見せるため。許可しなくても動く）。
  端末の再起動・アプリの更新のあとは自動で再開する（`RECEIVE_BOOT_COMPLETED`）。

## 音楽が鳴っているのに「知らせが届いていません」と出るとき

音楽アプリは、再生を**始めるとき**に一度だけ知らせを出す。その瞬間に ikora が聞けなかった
（強制停止されていた、更新で入れ替わっていた）と、音楽アプリが次の再生を始めるまで付けられない。

1. 「動作の設定」の **「常駐して待つ」を ON** にする（まだなら）
2. 音楽アプリの再生を止め、**アプリ情報から「強制停止」** する。
   画面に出る「（音楽アプリ）のアプリ情報を開く」ボタンから行ける
3. 音楽アプリで再生し直す

**アプリ履歴から消すだけでは足りないことがある。** AQUOS R8 は、履歴から消したアプリを強制停止する
（ikora の終了理由に `[REMOVE TASK] remove task` と記録された）。一方、再生中の YT Music は
履歴から消しても同じ再生（セッション）を続けたようで、新しい知らせが来なかった。
ikora 自身も、常駐していないと履歴から消したときに強制停止され、知らせを受けられなくなる。
「常駐して待つ」を ON にしてからは、この強制停止は記録されていない。

それでも届かないときは「全体モード」を使う。

## うまく動かないとき（診断）

DUMP を許可しなくても、次のものが画面に出る。テスターには「診断情報を送る」で送ってもらう。

- **出来事の記録**（最大 40 件、アプリが終わっても残る）: 音楽アプリからの知らせの受信、
  効果を付けられたか・付けられなかった理由、制御権を失った/取り戻した、常駐サービスが拒否された、など
- **知らせが来ていない**ことの判定: 音楽が鳴っている（`getActivePlaybackConfigurations`、権限不要）のに
  知らせを受けていなければ、そう表示して記録する。セッション ID は公開されていないので、
  ここから効果を付けることはできない
- **ほかの効果（種類だけ）**: イコライザ・低音強調・バーチャライザ・音量強調・DynamicsProcessing を、
  最低の優先度で付けてすぐ外すことで調べる。持ち主のアプリ名は分からない。
  付け外しは音の流れに触れるので、画面を開いたときとボタンを押したときだけ行う
- **受信テスト**: 音楽アプリと同じ届け方（宛先なし＋`FLAG_RECEIVER_INCLUDE_BACKGROUND`）で、
  ikora 専用の名前の知らせを自分に送り、登録の受け口と動的な受け口に届くかを見る。
  他のイコライザには届かない名前なので、よそに影響しない。
  - 両方届く → 端末は届けている。届かないのは音楽アプリが送っていない（か、ikora が見えていない）
  - 登録の受け口だけ届かない → 端末が裏のアプリへの配達を止めている
- **二つの受け口**: インストール時に登録する受け口に加え、プロセスが生きている間だけ動的な受け口も置き、
  どちらで受けたかを記録する
- **診断情報**: 機種、Android の版、上の状態（モード・常駐サービス・通知の許可も）、受信テストの結果、
  音楽アプリの版、ikora の過去の終了理由（Android 11+）、いま鳴っている音、端末が持つ音響効果の一覧、出来事

YT Music（9.38.51, Xperia）は知らせを宛先なしで 1 通だけ送り、`FLAG_RECEIVER_INCLUDE_BACKGROUND`
付きなので、受信登録している全アプリ（Poweramp Equalizer、Wavelet、MusicFX、ikora）に同時に届く。
MusicFX などの中継には頼っていない。

## ほかのイコライザと重なったとき

同じ種類の効果（DynamicsProcessing）は 1 セッションに 1 つしか作られず、優先度の高いアプリが
設定を握る。Poweramp Equalizer は優先度 1337 で付けるので、その間 ikora は設定できない。
v1〜v2 はこのとき端末の 5 バンド Equalizer に切り替えて**重ねがけ**になっていたが、
v3 からは切り替えず「効いていません」と表示する。相手が外れたら、画面を開いている間は
2 秒以内に自動で付き直す。

5 バンドという数は、端末標準の Equalizer（多くの機種で 5 バンド固定）から来ている。
DynamicsProcessing はバンド数も周波数も自由に決められるので、ikora は 7 にしている。

## 仕組み

- 音楽アプリは再生の始めと終わりに `OPEN_AUDIO_EFFECT_CONTROL_SESSION` /
  `CLOSE_…` を送る。それを受けて、そのセッションに DynamicsProcessing の 7 バンドを付ける。
- DynamicsProcessing は Android 9 から全機種にあるので、**どの端末でも同じ 7 バンド**になる。
  DynamicsProcessing そのものが無い端末に限り、端末の Equalizer に同じ曲線を当てはめて代わりにする。
- 常駐はエフェクトが付いている間だけ。セッションが無くなるとサービスは自分で止まる。
- 強制終了されたプレーヤーは CLOSE を送らないので、同じアプリが新しいセッションを開いたら
  古いほうを捨てる。
- 開いているセッションは保存しておき、ikora のプロセスが入れ替わったとき（更新・強制停止・メモリ回収）に
  付け直す。プレーヤーは再生開始時に一度しか知らせないので、これが無いと再生し直すまで効かない。
  v8〜v11 は音楽が鳴っていないと復元しなかったが、更新は音楽を一時停止して入れることが多く、
  再開は同じセッションの続きで知らせが来ないため、更新のたびにプレーヤーの強制停止が要った（テスターの苦情、
  Xperia で再現）。v12 からは鳴っていなくても付け直す。終わっていたセッションに付けても害はなく、
  プレーヤーの次のセッションで置き換わる。止まっている間の画面は「付いています（再生を待っています）」
- YT Music の設定 → 再生 → イコライザーは、この端末では MusicFX を経由して Sony の
  「オーディオ設定」に固定で飛ぶ。ikora の画面はホームのアイコンから開く。
- ほかのイコライザ（Poweramp Equalizer など）も同じセッションに効果を付けていると、
  重ねがけになる。
